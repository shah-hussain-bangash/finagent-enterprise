# Events (prompt §21)

Contract: [`packages/contracts/events/envelope.v1.schema.json`](../../packages/contracts/events/envelope.v1.schema.json)
and [`event-types.json`](../../packages/contracts/events/event-types.json), generated by
`scripts/export_event_schemas.py` from `finagent.worker.events`.

## Envelope v1

| Field | Meaning |
|---|---|
| `event_id` | Delivery identity = outbox row id. Never the business key (DIR-022). |
| `event_type` | One of the registered types below. Anything else is dead-lettered. |
| `schema_version` | Payload version for the type. |
| `tenant_ref` | Owning tenant. Consumers check it exists, is active, and owns the referenced resource. |
| `resource_id` | Case, run, operation or grant id. |
| `occurred_at`, `correlation_id` | Time of the business change; trace correlation (prompt §25). |
| `producer` | `finagent-outbox`. |
| `payload` | **References only** (ids, statuses). Never case content, customer data or findings. |
| `signature` | HMAC-SHA256 over the canonical JSON without `signature` (`event_signing_key`). |

## Delivery guarantees

- **Producer:** business change + audit + outbox row in one transaction. The relay publishes with
  `FOR UPDATE SKIP LOCKED` and marks the row published afterwards. Delivery is **at least once**.
- **Consumer:** envelope shape, signature, known type and active tenant are validated. Then, in ONE
  transaction, the inbox row `(tenant, consumer, event_id)` is inserted and the handler runs, so a
  duplicate is acknowledged without running the handler again.
- **Poison handling:** malformed, forged, unknown-type and cross-tenant events go straight to
  `dead_letters`, with no retry. A failing handler is released with backoff and dead-lettered after
  `consumer_max_deliveries` (default 5). Dead letters are owned by `PLATFORM_OPERATOR`.
- **Queue backends:** PostgreSQL table `queue_messages` (local default) or Azure Service Bus (the
  `message_id` is the event id, which enables duplicate detection). Service Bus is **LIVE
  INTEGRATION NOT VERIFIED**.

## Event types

| Type | Emitted when |
|---|---|
| `case.created.v1` | Alert intake created a case |
| `case.assigned.v1` | Supervisor (re)assignment |
| `case.status_changed.v1`, `case.blocked.v1`, `case.cancelled.v1`, `case.awaiting_review.v1`, `case.completed.v1` | Case status transitions |
| `case.escalated.v1` | A due-time escalation was raised (FR-011) |
| `workflow.started.v1` | Run queued by `POST /api/v1/workflows` |
| `workflow.resume_requested.v1` | Deterministic resume (approval/evidence services) |
| `workflow.awaiting_review.v1`, `workflow.completed.v1`, `workflow.failed.v1`, `workflow.cancelled.v1` | Run status changes |
| `approval.requested.v1` | Report version + snapshot frozen into a review request (submission) |
| `approval.decided.v1` | Reviewer decision (APPROVE / RETURN_FOR_REWORK / REQUEST_INFORMATION / REJECT) |
| `approval.invalidated.v1` | A material change invalidated a pending/approved request |
| `report.version_created.v1`, `report.submitted.v1`, `report.withdrawn.v1` | Report revisions and submission lifecycle |
| `document.received.v1`, `document.processed.v1` | Upload/fetch accepted (STORED or QUARANTINED); parser outcome |
| `evidence.snapshot_created.v1`, `evidence.material_change.v1` | Immutable snapshot frozen; reviewed facts changed |
| `policy.version_changed.v1` | Policy version ingested/approved/retired/revoked/reindexed |
| `export.created.v1` | Authorized report export produced |
| `external_operation.uncertain.v1` | An external effect's outcome could not be proven; reconciliation needed |
| `security.break_glass_activated.v1` | Emergency access activated (alert) |
