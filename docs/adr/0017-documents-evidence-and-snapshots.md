# ADR-0017: Documents, isolated parsing and immutable evidence snapshots

Status: Accepted (engineering) - 2026-10-16

## Context
FR-013..016, DIR-014, AER-017, SPR-012/017 require validated, scanned uploads, bounded parsing with
provenance, versioned evidence, contradictions kept with reasons, immutable snapshots and short-lived
downloads, all tenant-isolated.

## Decision
- Uploads are raw request bodies read with a hard byte counter after authentication (no multipart
  dependency; a false/missing Content-Length cannot bypass the 20 MiB PROPOSED limit).
- Declared type must be PDF/DOCX/CSV AND match the file signature; macros, OLE containers, signature
  mismatches and malware go to a quarantine namespace (kept for investigation, never parsed or
  downloadable). Scanner port: `LocalTestSignatureScanner` (EICAR; local/test only) and `ClamdScanner`.
- Parsing runs in a child interpreter (`python -I`) with a wall-clock timeout and a self-applied memory
  cap (RLIMIT_AS on POSIX; Windows Job Object incl. active-process limit). pypdf decompression caps,
  DOCX zip-ratio/size guards, defusedxml, CSV row/column limits. Encrypted -> quarantine (DATA-D04).
- Blobs: tenant/namespace/uuid keys generated by the platform, AES-256-GCM with the key as AAD.
- Evidence items are versioned per (case, source, ref); new version on content OR as-of change; only
  content changes are material. Snapshots and snapshot items are immutable (DB trigger for every role).
- Download links: HMAC tokens bound to tenant + principal + exact version, 300 s TTL, redeemed only by
  the same authenticated principal with CURRENT permission and case scope.

## Consequences
Parser memory limits are enforced on Windows and Linux (tested on Windows). OCR is an explicit
`OCR_UNAVAILABLE` state until an OCR provider is approved. Blob writes before commit can orphan an
object on rollback (harmless, encrypted; cleanup job is future work).
